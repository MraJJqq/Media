# 全历史持久化缓存原则

本规范是 VEGAS 素材库 K 线系统的统一缓存标准。缓存策略与图表显示、手势、EMA 绘制、品种轮播相互独立。

## 1. 历史范围
- 每个品种、每个周期，尽可能获取行情源实际提供的全部历史 K 线。
- 不设置固定年限、固定根数或人为截断上限。
- 交易所接口分页到达可探测的历史边界后，记录为“接口历史边界已探测”；不得把请求失败、限流或分页异常当作历史结束。
- 指标所需的最少历史数量只用于判断指标是否可用，不是缓存上限。

## 2. 持久化与隔离
- 使用 IndexedDB 持久化 K 线，不以页面内存作为唯一缓存。
- 缓存键必须由“交易所/数据源 + 品种 + 周期”组成；不同周期、不同数据源不得共用同一条缓存记录。
- 记录数据条数、最早/最新时间、最后更新时间、历史边界状态和缓存结构版本。
- 写入前按 K 线时间戳去重并升序排列；保留交易所原始 OHLC 数据，不人为偏移或合成价格。

## 3. 加载与更新顺序
1. 先读取本地持久缓存并立即供图表使用。
2. 再请求最新行情，合并新增 K 线。
3. 检测缓存末端与最新行情之间是否存在时间缺口；存在则分页补齐，不能只追加最新几根而留下断层。
4. 从最早缓存时间继续向前分页，直到探测到接口历史边界。
5. 只写入新增或修正后的数据，不反复全量下载已有历史。

## 4. 补齐任务
- 历史补齐队列与当前选中品种、轮播、图表重绘和手势生命周期解耦。
- 每个品种/周期独立保存补齐进度；一个任务失败不得阻断其他品种。
- 页面隐藏或关闭时，浏览器请求可能暂停；恢复或重新打开后从 IndexedDB 已保存的位置续传。
- 对限流、网络失败、超时和分页停滞进行区分；失败不得写入“已完成”状态。
- 控制并发和请求频率，避免大量品种同时请求。

## 5. 完整性状态
每个品种/周期至少记录：
- 历史最早时间、最新时间、缓存条数；
- 向前历史是否已探测到接口边界；
- 最新端是否存在缺口；
- 最近一次请求结果及失败原因；
- 缓存结构版本。

只有历史端与最新端均无未解决缺口，且历史分页已探测到接口边界，才可标记为完整。该状态表示“按当前接口分页规则已探测到边界”，不宣称交易所绝对不存在更早数据。

## 6. 当前素材库实现范围
- `kline/v5-kline-controller.js` 当前执行 Bitget USDT 合约 4H 缓存。
- 当前实现按品种队列补齐、持久化、增量更新，并检测修复最新端及缓存内部时间缺口；切换品种不取消历史队列。
- 其他周期接入时，必须使用独立缓存键和独立进度，不得复用 4H 的完成标记。
- 本规范不授权改变任何页面布局、图表视觉、EMA 参数、手势、轮播节奏或数据源。

## 7. Gate K 线控制器执行要求
以下要求适用于 `kline/gate-kline-controller.js`，也是 V6 的执行标准：

1. **缓存读取不得等待网络**：品种与合约映射已由本地配置提供，切换品种时先读取对应 IndexedDB 记录并立即绘制；不得先请求 Gate 合约列表再读缓存。
2. **三个流程独立启动**：缓存绘制完成后，立即启动历史补齐队列、WebSocket订阅；最新行情通过独立后台任务更新，不得让最新行情请求成为历史队列启动的前置条件。
3. **最新行情请求去重**：同一“合约+周期”共享进行中的最新行情请求；普通品种轮播在60秒内不重复发起同一最新行情请求。定时刷新可主动刷新，但必须与进行中的请求合并。
4. **并发写入合并**：最新行情、WebSocket和历史补齐可能同时更新同一缓存键。IndexedDB写入必须在同一读写事务内合并记录，按时间戳去重排序，不能用较旧快照覆盖另一流程新写入的数据；最新行情/WebSocket的新值优先修正相同时间戳K线。
5. **完整性状态分离**：`historyBoundaryReached`只代表向前分页已探测到接口边界；`latestGapStatus`只在最新行情成功核验后标记为`clear`。两项都满足才可标记`historyComplete`。
6. **轮播隔离**：轮播只改变当前显示品种和行情订阅，不得重置、取消或重复创建历史补齐任务；缓存读取和请求去重按“合约+周期”独立执行。
